# Flow-Skill 文件路径契约

> 版本：0.2.0 设计稿（待实现）
> 状态：设计定稿，未经实现
> 关联文档：`输入输出契约设计.md`（inputs/outputs 声明契约，本文是其路径部分的完整化）、`Skill接入说明.md`（V1 行为）

---

## 1. 目标与问题

0.1.x 的路径处理有四类隐患：

| 隐患 | 现状 |
|---|---|
| Run 数据位置由 Agent 决定 | `data_dir` 默认 `.flow-data` 相对 CWD，会话漂移 → 数据散落、旧 Run 查不到 |
| instruction 基准未定义 | `tasks/collect.md` 相对谁？代码文档都没说，依赖"Agent CWD 恰好是技能目录"的隐含假设 |
| 产物路径零校验 | result 里的路径字符串原样入库传下游，越界/不存在/格式不符畅通无阻 |
| 输入文件包不落位 | `workspace/inputs/` 建了目录但从不写入，靠 Agent 自觉 |

本契约把全部路径纳入三类基准目录体系，每条路径都有**确定的基准、确定的书写规范、确定的核验规则**。

### 不变式

- 包零第三方依赖：路径核验只用标准库（`pathlib`、`zipfile`）；
- 路径核验失败一律走现有 `rejected` / 定义期报错通道，状态机不加状态；
- 核心原则：**包只定基准与核验，绝不为失败"换地方"——报错可行动，降级要声明**。

---

## 2. 基准目录体系（三类）

```text
┌─────────────────────────────────────────────────────────────┐
│ 技能目录 base_dir（只读：定义与指令）                          │
│   workflow.py / tasks/*.md / references/                    │
│   → instruction 相对路径的基准（§4）                          │
├─────────────────────────────────────────────────────────────┤
│ Run Workspace（每 Run 一个：产物与工作区）                     │
│   <data_dir>/<flow-name>/runs/<run-id>/                     │
│   → FileOutput.path / FileInput 装配 / ctx.resolve 的基准（§3）│
├─────────────────────────────────────────────────────────────┤
│ 数据目录 data_dir（包管理：数据库与 Run 集合）                 │
│   → 由解析链 + 注册表确定（§5）                               │
└─────────────────────────────────────────────────────────────┘
```

规则：技能目录可能随 Skill 重装被覆盖 → **禁止存放 Run 数据**；会话工作目录跨会话漂移 → **禁止作为任何契约路径的基准**（`.flow-data` 兜底仅为 0.1.x 兼容）。

## 3. Run Workspace 路径契约（产物路径）

### 3.1 书写规范（定义期强制）

FileOutput.path 及一切"相对 workspace"的路径字符串必须满足：

```text
1. 相对路径        以 / 或盘符开头 → 定义期报错
2. 禁止上跳        含 .. 段 → 定义期报错
3. 正斜杠存储      统一用 / 分隔（跨平台一致）；Windows 解析时由包转换
4. 空路径非法       path 为空 → 定义期报错
```

规范化函数（包内唯一实现，定义期与提交期共用）：

```python
def normalize_workspace_path(path: str) -> PurePosixPath:
    p = PurePosixPath(path.replace("\\", "/"))
    if p.is_absolute() or ".." in p.parts or path.strip() == "":
        raise ValidationError(f"路径 '{path}' 非法：必须是不含 .. 的 workspace 相对路径")
    return p
```

### 3.2 推荐布局（约定，不强制前缀）

```text
<workspace>/
  inputs/               ← Run 级原始输入（包落位，见 §6）
  working/<task_id>/    ← 任务私有工作区（领取时自动创建）
  outputs/              ← 最终产物（FileOutput.path 的常规落点）
```

契约不强制 path 以 `outputs/` 开头——特殊布局（如产物就在根目录）合法，但文档推荐统一 `outputs/`。

### 3.3 提交期核验规则

| 规则 | 说明 |
|---|---|
| path 一致性 | FileOutput 声明了 path 时，result[name] 必须与之**精确一致**（规范化后比较），杜绝"声明 A 提交 B" |
| workspace 内 | result[name] 解析后必须位于 workspace root 内（防越界写别处） |
| 文件存在 | `Path.exists()` 标准库检查 |
| 扩展名 | 与 format 声明一致 |
| metadata 核验 | 按 format 查表分发（xlsx sheet 清单 / md 标题 / html 片段），见输入输出契约设计 §3.2 |

### 3.4 共享工作簿（同一路径多任务声明）

多个任务的 FileOutput.path 指向同一路径 → **合法**（Excel 单工作簿模式），附加规则：

- format 必须一致（一个 xlsx 一个 csv 指同一路径 → 定义期报错）；
- 以 sheet 划分所有权：`<task_id>__<子表名>` 前缀，孤儿 sheet 提交被拒；
- 包不创建不解析文件内容：文件由第一个写它的任务创建，提交期核验存在性即可。

## 4. 技能目录路径契约（instruction 与 base_dir）

### 4.1 base_dir 的确定

```text
Flow(base_dir=...) 显式指定 → 用它
未指定 → CLI 从 --workflow 指定的 workflow.py 所在目录自动探测
```

Agent 能执行 workflow.py 就必然能读它旁边的 tasks/*.md——所以默认探测已经正确，作者通常无需显式指定。

### 4.2 instruction 解析

```text
定义期：agent/human 的 instruction 相对路径 → 用 base_dir 解析为绝对路径存库
        绝对路径 → 原样存库
        同时保留 instruction_raw（原文，审计用）
领取期：payload 的 instruction 永远是绝对路径，与 Agent 的 CWD 无关
```

指令引用的其他技能文件（validator 里读模板、references/）同样遵循 base_dir 基准——提供 `flow.base_dir` 属性供定义代码使用。

## 5. 数据目录契约（data_dir 解析链 + 注册表）

### 5.1 create-run：解析链

```text
1. CLI --data-dir              显式传参，最高优先
2. FLOW_SKILL_DATA_DIR         环境变量（所有技能共享的根，之下按 flow-name 分子目录）
3. Flow.default_data_dir       Skill 作者在 workflow.py 里定义
4. ".flow-data"                CWD 兜底（仅为 0.1.x 兼容，正常应走不到）
```

解析结果落地前**探针写入**（写临时文件再删）：不可写 → 报错 `"数据目录 <path> 不可写。请用 --data-dir 指定当前环境可访问的持久目录"`。**绝不静默换地方**。

### 5.2 注册表：run_id → data_dir，包替 Agent 记路

**位置解析**（每技能一份，天然隔离多技能）：

```text
1. FLOW_SKILL_REGISTRY 环境变量
2. workflow.py 同目录的 .flow-registry.json
   （Agent 能执行 workflow.py 就必然能写它旁边；只存映射，重装丢失时可显式 --data-dir 恢复）
3. 写失败 → 降级为无注册表模式（行为回到 0.1.x），status 输出中明确注明
```

**结构与写入**：

```json
{
  "version": 1,
  "runs": {
    "run_a1b2c3": {
      "data_dir": "C:/.../flow-data",
      "flow_name": "shop-report",
      "flow_version": "1.0",
      "skill_path": "C:/skills/shop-report/workflow.py"
    }
  }
}
```

原子写入（临时文件 + `os.replace`）；映射基本只增不改，多进程并发 last-write-wins 可忽略。

### 5.3 续跑：注册表是唯一事实源

```text
1. 注册表命中 → 用注册路径，并校验 flow_name / flow_version / skill_path
   ├─ 未传 --data-dir → 正常执行（绝大多数情况，全自动）
   └─ 传了 --data-dir 且 ≠ 注册路径 → 报错：
      "该 Run 注册于 A，与 --data-dir B 不一致。若数据确已迁移，请加 --rebind 改绑"
2. 注册表未命中（存量 Run / 注册表丢失）→ 用 --data-dir（0.1.x 兼容）
3. 两者都没有 → 报错并提示先 create-run
```

**--rebind 是唯一改绑通道**：`--data-dir B --rebind` → 更新注册表记录，之后恢复全自动。所有改变 Run 位置的操作都必须经过这个语义明确的显式标志——自动化路径上不允许出现"另一个位置也说得通"的分支。

### 5.4 冲突防护

| 规则 | 说明 |
|---|---|
| 重复 create-run | run_id 已注册但 data_dir 不同 → 报错（防同 run_id 两处建假 Run） |
| 注册位置失效 | 注册表命中但目录不存在（被挪/清理）→ 报错提示显式传 --data-dir |
| 技能同名冲突 | flow_name 相同但 skill_path 不同 → 报错（两个技能重名共用 data_dir 时第一次就拦住） |
| 存量收编 | 未注册的 Run 用 --data-dir 成功访问后，可 `--register` 手动收编进注册表 |

### 5.5 多技能隔离

- 注册表**每技能一份**（workflow.py 旁边），命令行 `--workflow` 已绑定技能，跨技能查错在结构上不可能；
- 共享 `FLOW_SKILL_DATA_DIR` 时按 flow-name 分子目录，flow 名全局唯一从"建议"升级为"硬要求"（5.4 指纹校验兜底）；
- 推荐各技能写自己的 `default_data_dir`（如用户级固定目录），物理隔离。

## 6. 输入落位契约

`create-run --inputs-file <path>`（绝对或 CWD 相对——调用时现场给定，基准是进程 CWD，这是唯一合法的 CWD 相对场景）：

```text
JSON 入库（现状不变）+ 包自动把文件拷贝到 <workspace>/inputs/<原文件名>
并在 Run inputs 里记录 inputs_source: "inputs/<原文件名>"
目标重名 → 报错（不覆盖）
```

之后全流程用 workspace 内路径引用原始输入，物理位置由包确定。

---

## 7. ctx 工具语义（validator / when 用）

```python
ctx.resolve("outputs/run.xlsx")
# 相对路径 → workspace 内绝对路径（normalize + join）
# 绝对路径 → 原样返回（是否越界由调用方用下一行判断）

ctx.is_within_workspace(path)
# 解析后严格判断 path 在 workspace root 内（含 symlink 逃逸检查：
# resolve() 后再比对前缀，防软链接指向 workspace 外）

ctx.workspace          # workspace root 绝对路径
ctx.base_dir           # 技能目录绝对路径（Flow.base_dir）
```

## 9. 测试场景清单

1. **定义期**：绝对路径 / `..` / 空 path / 反斜杠混用 → 报错或规范化；共享工作簿 format 不一致 → 报错；
2. **解析链**：--data-dir / 环境变量 / default_data_dir / 兜底四级各自生效与优先级；探针不可写 → 可行动报错；
3. **注册表**：create 后免 --data-dir 续跑；传不一致路径 → 报错；--rebind 改绑后全自动跟随；注册表文件删除 → 降级可用；重复 create-run 拦截；技能指纹冲突拦截；
4. **instruction**：相对路径经 base_dir 解析为绝对路径；换 CWD 重跑 instruction 仍正确；
5. **ctx 工具**：resolve 相对/绝对；is_within_workspace 对 `..`、绝对外部路径、symlink 逃逸的判定；
6. **输入落位**：--inputs-file 拷贝到 workspace/inputs/ 且 inputs_source 记录正确；重名报错；
7. **端到端**：新会话换 CWD 续跑旧 Run（免路径参数）→ 全程正常。
